## 一、需求与业务概念(ITIL/ITSM 领域)

> 开发工单类系统,业务概念不清是最大返工来源。以下概念必须先统一口径,再动手写代码。

### 1.1 必须精通(直接决定表设计与接口)

| 概念 | 一句话解释 | 影响的设计点 |
|------|-----------|-------------|
| 事件 Incident | 计划外的服务中断/质量下降,目标是**尽快恢复** | 状态机、解决时限 SLA |
| 服务请求 Service Request | 预定义的标准服务申请(如开通账号),走**预置审批** | 目录条目 + 表单模板 + 审批流 |
| 问题 Problem | 重复事件/重大事件背后的**未知根因** | 问题单关联事件表 |
| 已知错误 Known Error | 根因已定位、临时措施已有,永久修复待实施 | 问题单状态标记 + 检索 |
| 变更 Change | 对生产环境的有受控修改,目标是**降低风险** | 审批层级 × 风险等级 |
| 回退方案 Rollback | 变更失败时的恢复手段 | 变更申请必填项 |
| 优先级矩阵 | 优先级 = 紧急度(Urgency)× 影响度(Impact) | 定级接口,P1~P4 |
| SLA / 时限 | 响应时限(MTTA 目标)与解决时限(MTTR 目标) | 计时实例表、暂停/恢复 |
| 升级 Escalation | 超时后按层级通知上级(层级升级)或转更专业组(功能升级) | 定时任务 + 通知 |
| 数据范围 | 本人/本组/本部门/全部的可见性 | RBAC 数据权限实现 |

### 1.2 需要了解(影响细节口径)

| 概念 | 解释 |
|------|------|
| 统一受理台 | 所有渠道的工单先汇聚到待受理池,再人工/自动分派 |
| 时间线(Timeline) | 工单全部动作(受理/回复/转派/挂起…)的只读留痕,不可篡改 |
| 重开窗口 | 关单后 N 天内可重开(默认 7 天,参数可配) |
| 自动关单 | 解决后 N 天用户未确认,自动关闭(默认 3 天) |
| 挂起与 SLA 暂停 | 等待用户/等待供应商时解决时钟暂停,恢复后续计 |
| 满意度 CSAT | 关单前 1~5 分评价,一次有效 |
| 变更日历 | 已批准变更按时间窗口展示,人工目视避让冲突(精简版不做自动检测) |
| 紧急变更 | 走加急审批,事后补评估记录 |

### 1.3 参考资料

- ITIL 4 Foundation 认证教材(重点读 4 个实践章节:Incident / Service Request / Problem / Change Enablement);
- 团队内部:先通读《产品设计文档-精简版》第 4 章,对每张流程图达成一致。

## 二、技术清单(按功能域映射)

> 标注:【精通】= 需能独立设计与排错;【熟练】= 能按文档使用;【了解】= 知道原理与选型理由。

### 2.1 后端公共底座

| 技术/概念 | 掌握程度 | 用在哪里 |
|-----------|---------|---------|
| Java 17(record、switch 表达式、文本块) | 熟练 | 全部 |
| Spring Boot 3:自动装配、条件注解(`@ConditionalOn*`)、`AutoConfiguration.imports` | 精通 | 三大可插拔 starter |
| Spring MVC + RESTful 规范 + 全局异常处理 | 精通 | 全部接口 |
| Bean Validation(`@Valid` + 自定义校验器) | 熟练 | 表单数据提交校验 |
| Spring 事务(`@Transactional` 传播行为、事务边界) | 精通 | 工单动作与 Flowable **同库同事务** |
| Spring AOP | 熟练 | 操作审计切面 |
| Flyway 版本化迁移(增量脚本纪律) | 精通 | 所有 DDL/种子数据 |
| Lombok / MapStruct(可选) | 熟练 | DO/DTO 转换 |

### 2.2 认证与权限(M1 平台底座)

| 技术/概念 | 掌握程度 | 用在哪里 |
|-----------|---------|---------|
| Spring Security 6(过滤链、`SecurityFilterChain`) | 精通 | 无状态安全配置 |
| JWT(jjwt:签名算法、过期/刷新、无状态注销思路) | 精通 | 登录/刷新/登出 |
| BCrypt 密码散列 + 登录失败锁定 | 熟练 | 账号安全 |
| RBAC 模型(用户-角色-权限点;菜单/按钮/接口三级) | 精通 | 权限表设计 + 接口 Guard |
| 数据范围过滤(本人/本组/本部门/全部) | 精通 | 工单列表/详情越权防护(实现:统一查询条件拼接或 MyBatis 拦截器) |
| 方法级注解鉴权(`@PreAuthorize` / 自定义 `@RequirePerm`) | 熟练 | 接口权限点 |

### 2.3 数据访问与 PostgreSQL

| 技术/概念 | 掌握程度 | 用在哪里 |

## 三、建议学习路径

### 后端(第 1 周内完成,与 M1 并行)

1. **第 1~2 天**:Spring Security 6 + JWT 完整跑通一个 demo(登录/刷新/鉴权/数据范围)→ 直接服务 M1;
2. **第 3~4 天**:Flowable 官方 Quick Start + 一个含「顺序多实例审批」的最小流程 demo → 验证审批人解析方案;
3. **第 5 天**:PostgreSQL JSONB + GIN 索引实践;Redis ZSET 实现一个「超时扫描」mini-demo → 服务 SLA;
4. **持续**:ITIL 四个实践的概念口径对齐(见 1.1 表),配合产品设计文档流程图评审。

### 前端(第 1 周内完成)

1. **第 1~2 天**:登录守卫 + token 刷新 + axios 拦截器改造 → 服务 M1;
2. **第 3~5 天**:动态表单渲染原型(先支持 文本/下拉/日期/人员/附件 5 类控件)→ 决定 M2 表单方案;
3. **持续**:msw mock 与接口契约同步(每个迭代第 1 天冻结契约)。
